Zapier: cross-site planting of an enabled, self-running Zap via a guided template — CRITICAL

A template author's stored zsl.zaps[0].enabled and each step's authentication_id are applied to the Zap created in the consumer's account. The consumer reviews nothing, enables nothing, and the planted Zap runs itself.

Requirements
  • A different account from the template author must be logged in to zapier.com in this browser — that account receives the Zap.
  • Chrome, or any browser attaching zapier.com cookies cross-site. Credentialed cross-site "simple" request — no preflight, no CSRF token.
  • Open DevTools ▸ Network first. The response is cross-origin-unreadable — expected, and irrelevant: nothing here needs to read it.
  • Zero-click: fires on load when the values are present.
Verify in the victim account 
GET /api/gulliver/storage/v1/zaps/<new zap id>?account_id=<victim>
→ { "is_enabled": true,
    "current_version": { "version_number": 1, "subscription": true } }

The enabled:false counterpart produces "is_enabled": false, "current_version": null. That pairing is the control.
